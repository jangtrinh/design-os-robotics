Install once

Clone the repository and verify the local Python toolchain and Spec-Driven benchmark suite from your terminal.

git clone https://github.com/jangtrinh/design-os-robotics.git
cd design-os-robotics
python3 tools/benchmark-avatar-perf.py
python3 tools/mochi-soul-engine/engine.py --benchmark

First safe use

  1. Run the non-intrusive 4-layer hardware health check (uses ~HUPCL so a connected robot is never reset). 
    ./tools/robotctl.py health
  2. Inspect the decoded NVS partition parameters and active esp_mmap_assets checksum in read-only mode. 
    ./tools/robotctl.py status
  3. Execute the 60fps spring reflex and Xiaozhi proactive bridge verification suites offline before flashing. 
    python3 tools/mochi-soul-engine/bridge.py --benchmark && python3 tools/mochi-soul-engine/reflex_60fps.py --benchmark

Every benchmark writes a machine-checkable JSON report into plans/reports/ before any partition mutation is performed.

A practical loop

Four deterministic commands cover diagnostics, procedural asset compilation, soul simulation, and hardware flashing.

health

Audits USB-JTAG, LAN ARP/ICMP latency, Tenclass TLS, NVS CRC32, and passive UART logs via ./tools/robotctl.py health.

cook-procedural

Synthesizes all 21 procedural Mochi GIFs (244.71 KB) and packs the Procedural Mochi-21 240×320 asset binary (checksum 0x5867).

soul-benchmark

Verifies Spec 02 (~0.75 µs/tick measured idle), Spec 03 (880/880 packets), and Spec 04 (2.36 µs/frame 60fps spring + lip-sync).

optimize --flash

Writes validated NVS (0x9000) and esp_mmap_assets (0xAA0000) at 921600 baud (`1,231.9 kbit/s` effective).

Frequently asked questions

What is DESIGN:OS Robotics?

DESIGN:OS Robotics is a source-available hardware control CLI, esp_mmap_assets theme compiler, 4-layer non-intrusive diagnostic dashboard, and Spec-Driven Generative AI Tamagotchi runtime (Project Mochi-Soul) built for ESP32-S3 N16R8 voice robots (RB5320XZ78AI / XiaoZhi78).

How does the 244.71 KB Procedural-21 Avatar save 90.4% flash over the default GIF pack?

Instead of shipping the default GIF pack of 2.56 MB of dithered 240x320 bitmap GIFs, cook-procedural-avatar.py synthesizes all 21 emotions from 582 lines of geometric math at 240x240 px with a locked 12-color Indexed LZW palette, achieving 681 average scanline RLE spans per frame.

How does robotctl.py inspect hardware health without resetting the ESP32-S3?

Standard esptool invocations toggle DTR and RTS lines on the USB-Serial/JTAG controller, triggering a hard chip reset. robotctl.py opens USB-JTAG with the termios ~HUPCL flag so DTR is never dropped, auditing USB-JTAG, ARP/ICMP LAN latency, voice-server TLS, NVS CRC32, and passive UART telemetry with zero conversation interruption.

How do the 4D Homeostasis Soul Engine and 60fps Spring Reflex work?

Spec 02 (engine.py) evolves a continuous 4D biological state vector (Energy, Valence, Bond, Curiosity) in ~0.75 us/tick (measured idle) with SQLite WAL persistence (~4.0 us/tx, median of 12 runs) and Quiet Hours guardrails (23:00–07:30). Spec 04 (reflex_60fps.py and mochi_face_60fps.hpp) integrates a 10-DOF second-order differential spring equation in 2.36 us/frame at 60Hz with r = 0.9592 lip-sync correlation.
